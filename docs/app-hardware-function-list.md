# AIPIN App - EVT V1.6 硬件联调功能清单

## 1. 文档范围

本文档只描述当前 `evt` 分支会与真实 V1.6 EVT 固件发生的交互，用于 App、固件和测试人员确认双方实际需要联调的功能。

本分支的硬件协议白名单只有：`0x01`、`0x02`、`0x05`、`0x06`、`0x07`、`0x09`（V1 六字节认证码）、`0x11`、`0x21`、`0x22`、`0x23`。

下列接口和能力不在 EVT 构建中，App 不会订阅、写入或请求：`0x08/FA18` 实时音频、`0x26/FF16` 文件元数据与归档确认、`0x09` V2 Ticket/Proof、OTA/WQOTA、云端票据、云端归档，以及未列入白名单的其他设备命令。

本机录音和 AI 文本处理属于 App 独立功能，不会向设备发送额外 BLE 协议，不在本清单的硬件联调范围内。

## 2. 固件必须提供的身份信息

下表是固件应提供的正式 EVT 广播身份。当前调试构建的手动扫描和自动回连都只要求名称非空，连接后以 GATT 合约作为可用性门槛；自动回连只会匹配本地已记录的同一设备，优先使用厂商数据中的物理地址，缺失时回退平台连接 ID：

| 广播字段 | 固件需要发送的值 | App 的检查方式 |
| --- | --- | --- |
| 本地名称 | `AIPIN_XXXX` | 当前扫描只要求名称非空；此格式用于固件验收和正式身份识别 |
| 厂商数据 | `A3 89 + BtAddressRaw[6]`，总长 8 字节 | 当前扫描不拦截；自动回连优先取其中的物理地址匹配 |
| 服务 UUID | `0000AF30-0000-1000-8000-00805F9B34FB` | 当前扫描不拦截；连接后由严格 GATT 合约决定是否可用 |

`connectionId` 只用于手机系统建立 BLE 连接。Android 通常会给出 MAC 地址；iOS 给出 CoreBluetooth UUID，不能当作 MAC 使用。App 回连同一台硬件时优先用厂商数据里的 6 字节物理地址匹配。

## 3. GATT 特征与 EVT 功能

所有特征 UUID 均为 `0000xxxx-1212-EFDE-1523-785FEABCD123`。App 会在连接后发现服务并按真实属性校验。`FA11`、`FA12`、`FA15`、`FA16`、`FA17`、`FA19`、`FB11`、`FF12`、`FF13` 是认证通道的硬性要求；任一缺失、属性不符或 CCC 订阅失败时，App 会中断本次会话。`FF11/0x21` 只是兼容性文件数摘要，存在时才订阅和读取，缺失或订阅失败不会阻止认证、文件列表或文件导入。

| 编号 | 用户或系统触发 | App 实际做什么 | 固件接口和必要属性 |
| --- | --- | --- | --- |
| E-01 | 打开“连接设备”、点击查找 | 请求平台权限，扫描名称非空的设备，按信号排序，5 秒未再次收到广播则从列表移除；手动连接后校验 EVT GATT 合约 | BLE 广播：正式身份为名称、`A3 89 + 6B`、`AF30`；GATT 合约决定是否可用 |
| E-02 | 选择设备后点击连接 | 停止扫描，建立 GATT 连接，发现服务和特征；先订阅 `FA11/FA19`，认证成功后再订阅业务 CCC | 九个必需 EVT 特征及各自规定属性必须都存在；`FF11` 为可选兼容特征 |
| E-03 | 用户输入认证码、首次绑定或恢复初始码 | 当前页面输入 12 位十六进制字符并解码为 6 个原始字节，向 `FA19` 发送 V1.6 `0x09`；只接受一字节 `0x89` 成功或失败结果 | `FA19 Write + Indicate`；Action 为 `0=认证`、`1=首次绑定`、`2=解绑/恢复初始码` |
| E-04 | V1 认证或绑定成功后自动 | 绑定成功时同连接追加 `Action=0`；订阅业务 CCC，读取 `0x01`，记录 `ProtocolVersion`，再写一次基础配置 | `FA11 Write + Indicate`，`FA12 Write + Indicate`；预认证 MTU 至少 `99`，认证态完整信息至少 `136` |
| E-05 | 首次同步或用户刷新 | 读取设备状态、电量、存储、当前设备时间、隐私时长；`FF11` 存在时再读取文件数，失败时保留最后有效值 | `0x06/FA16`、`FA15 Write + Indicate`、`FB11 Read`、`FA12 Read`、可选 `FF11 Write + Indicate` |
| E-06 | 修改设备录音授权或默认隐私时长 | 用 `0x06` 读取或设置状态；只在认证有效期内下发 | `FA16 Write + Indicate`；SubCmd `01/02/03/04` |
| E-07 | 点击设备开始、暂停、继续或结束录音 | 用 `0x07` 下发动作，收到 `0x87` 后才刷新页面状态；不会自动重发这类非幂等命令 | `FA17 Write + Indicate`；Action `0/1/2/3` |
| E-08 | 打开设备录音文件、导入文件 | 先用 `0x22` 分页取文件名和长度，再用 `0x23` 请求并持续接收 `0xA3` Notify 数据；断连后从已确认的 offset 继续 | `FF12 Write + Indicate`，`FF13 Write + Notify`；当前接受 `.m4a`、`.ogg`，纯数据单帧最多 480B |
| E-09 | 非用户主动断连 | 在前台重新扫描最近一次认证成功的设备，优先按物理地址匹配、缺失时按平台连接 ID 匹配，并最多尝试三次；新连接仍需重新认证 | 稳定广播身份有助于跨平台识别；App 不在后台持续扫描 |
| E-10 | 打开设备详情的实时日志 | 记录扫描、连接、服务发现、订阅、MTU、写入、响应、断连和回连；当前 Debug 的 `raw_packet_hex` 保留完整收发字节，可能包含认证码、文件名和音频数据，仅用于受控联调 | 无额外固件接口 |

## 4. 连接、认证与同步顺序

```text
扫描到名称非空的 BLE 广播（当前兼容扫描）
  -> 用户选择并连接
  -> GATT 服务发现和属性检查
  -> 订阅 FA11/FA19 预认证通道
  -> 预读 0x01 脱敏身份
  -> 用户执行 V1.6 认证或首次绑定（绑定后追加 00）
  -> 订阅其余 EVT 响应通道
  -> 校验 ATT MTU
  -> 0x01 读取认证态信息并记录 ProtocolVersion
  -> 0x02 写入本次会话基础配置
  -> 自动读取状态、电量、存储和文件数
  -> 进入可操作的设备详情页
```

CCC 分两阶段建立：预认证按 `FA11`、`FA19`；认证成功后按 `FA12`、`FA15`、`FA16`、`FA17`、`FB11`、`FF12`、`FF13`，最后在设备提供时订阅可选 `FF11`。任一必需订阅失败都会停止连接流程；`FF11` 缺失或订阅失败只会隐藏文件数摘要，不影响认证或文件导入。

App 的 V1 认证有效期为 60 秒。认证过期、认证失败或连接断开后，设备信息、配置、录音和文件操作都会停止，用户需重新认证。App 不请求网络票据，也不发送 Ticket、Proof、nonce 或 V2 认证包。

## 5. 指令收发规则

| 命令 | 发往特征 | 成功响应 | 作用 |
| --- | --- | --- | --- |
| `0x01` | `FA11` | `0x81` | 获取设备信息和协议版本 |
| `0x02` | `FA12` | `0x82` | 写入会话基础配置；设备时间读取使用 `FA12` GATT Read |
| `0x05` | `FA15` Write 空 Content | `0x85` Indicate | 获取总存储和剩余存储 |
| `0x06` | `FA16` | `0x86` | 读取状态，设置录音授权和默认隐私时长 |
| `0x07` | `FA17` | `0x87` | 控制开始、暂停、继续、结束录音 |
| `0x09` | `FA19` | `0x89` | V1 认证、首次绑定、恢复初始认证码 |
| `0x11` | `FB11` GATT Read | `0x91` | 获取电池和充电状态 |
| `0x21` | 可选 `FF11` Write 空 Content | `0xA1` Indicate | 获取兼容性设备文件数量摘要 |
| `0x22` | `FF12` | `0xA2` | 分页获取文件名和文件长度 |
| `0x23` | `FF13` | `0xA3` Notify 流 | 下载一个文件，零长度数据帧表示结束；纯 FileData 单帧最多 480B |

业务帧统一为 `[0xED][Length:u16LE][CMD:u8][Content...][CRC16:u16LE]`。CRC 使用 `CMD + Content` 上的 CRC-16/CCITT-FALSE，写入和长度字段使用小端序。App 会丢弃同步字、长度或 CRC 不正确的数据帧。

普通单次命令 2 秒没有匹配回复时最多再试一次。`0x07` 和 `0x09` 不自动重试，避免重复执行录音控制或绑定动作。`0x23` 从开始到结束独占命令队列，15 秒没有下一段数据则判定下载超时。

## 6. 平台处理

| 平台 | App 行为 |
| --- | --- |
| Android 6-11 | 扫描前请求定位权限，并要求系统定位服务处于开启状态 |
| Android 12 及以上 | 扫描前请求“附近设备”的蓝牙扫描和连接权限；蓝牙关闭时可弹出系统开启请求 |
| Android 8 及以上 | 使用 legacy 扫描模式，确保固件的 legacy 广播和 scan response 能被发现 |
| iOS 13 及以上 | 通过 CoreBluetooth 请求蓝牙授权；系统不允许 App 直接打开蓝牙，页面引导用户到系统设置或控制中心后重新扫描 |
| iOS 连接 ID | 不假设 iOS `connectionId` 是 MAC，回连依靠厂商广播中的稳定物理地址 |
| iOS Ogg/Opus 播放 | 当前 BLE 导入和保存可用，但系统 AVPlayer 不能原生播放 Ogg/Opus；在未引入转码或解码器前，不能把该播放能力列为 iOS 已完成项 |

## 7. 固件联调验收顺序

1. 用抓包或调试工具确认广播同时包含 `AIPIN_XXXX`、`A3 89 + 6B` 和 `AF30`。
2. 在 Android 和 iOS 各连接一次，确认九个必需 EVT 特征均存在且属性与第 3 节完全一致；先确认 `FA11/FA19` 预认证 CCC 和脱敏 `0x81`，认证后再确认其余必需 CCC 全部订阅成功；若固件提供 `FF11`，再验证它的可选写入、Indicate 和读取。
3. 分别用正确和错误的六字节认证码验证 `0x09 -> 0x89`，确认 App 不再请求“认证服务”。
4. 确认认证成功后依次出现 MTU、`0x01 -> 0x81`、`0x02 -> 0x82`，并且设备返回 `ProtocolVersion=3`。
5. 逐项验证 `0x06` 状态和配置、`0x07` 录音控制、`0x05` 存储、`0x11` 电池；固件提供 `FF11` 时再验证可选 `0x21` 文件数。
6. 用 `0x22` 获取一页文件，并以 `0x23` 进行一次完整下载和一次断连后续传。
7. 验证前台意外断连自动回连、主动断开不自动回连、蓝牙关闭和权限拒绝的提示。
8. 导出 Debug 日志，与固件日志按时间线核对特征、CMD、响应和错误。

更详细的字段布局、状态编码和异常处理见 [真实固件 V1.6 联调说明](real-firmware-integration.md)。
