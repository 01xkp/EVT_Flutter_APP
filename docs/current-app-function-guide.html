扫描附近设备

扫描只负责发现；真正连接前还会校验设备身份数据。

操作流程

已开放
用户操作
  1. 首页点击设备卡片，进入“连接设备”。
  2. 点击“查找附近设备”。
  3. 蓝牙关闭时按系统提示开启蓝牙。
  4. 选择设备后点击“连接设备”。
扫描规则
  • 没有名称的 BLE 设备不显示。
  • 相同连接 ID 只保留一条，后续广播更新 RSSI 和最后出现时间。
  • 列表按 RSSI 从强到弱排序。
  • 约 5 秒未收到新广播的设备从列表移除。
  • 当前 EVT 调试构建只要求名称非空即可展示并允许手动连接；没有名称的设备不显示。
  • 手动连接后才校验九个必需 EVT GATT 特征及属性；不符合 GATT 合约的设备不会进入认证。AIPIN_XXXX、A3 89 + 6B、AF30 仍是自动回连的严格身份合同。
平台处理

Android 12+ 使用附近设备权限；Android 10/11 按系统要求检查定位权限和定位服务。iOS 使用 CoreBluetooth 授权。Android 可以请求系统打开蓝牙；iOS 只能引导用户前往系统设置或控制中心开启后返回。

连接与 GATT 初始化

连接成功不等于可控制设备。App 必须完成服务发现、认证通道订阅和 V1 认证后才开放受保护功能。

连接步骤

已开放
App 执行
  1. 停止扫描并建立 BLE 连接。
  2. 发现全部 GATT 服务和特征值。
  3. 校验九个必需 EVT 特征值均存在，并逐项校验协议规定的 Read、Write、Indicate 或 Notify 属性；FF11 仅作可选兼容检查。
  4. 按 EVT 固定顺序订阅九个必需业务特征值的 CCC 通道；存在 FF11 时再订阅其可选通道。
  5. 进入“等待设备认证”，不发送其他受保护业务命令。
失败处理
  • 连接和服务发现均有约 15 秒保护时间。
  • 任一 EVT 特征缺失、属性不符或 CCC 订阅失败：会话中断，不能认证。
  • 错误会写入实时日志，需由固件修正完整 GATT 合同后重新连接。
  • 断开时取消订阅、取消待发送命令并进入可重连状态。

认证后初始化

认证成功后自动执行
App 操作

请求 ATT MTU，要求实际协商值至少为 136；发送 0x01 读取设备信息，要求设备返回协议版本 3；再发送 0x02 写入 EVT 默认配置。

结果

初始化成功后进入状态可观察阶段，开放状态、配置、设备录音和文件导入。关键步骤失败会中断并断开，避免“已连接但数据不完整”的状态。

认证、首次绑定、恢复初始码

当前只实现 V1 本地六字节认证，不调用云端认证服务，不使用 V2 Ticket。

功能用户操作协议动作成功后
认证设备点“认证设备”，输入当前 6 字节认证码。向 FA19 写入 V1 0x09，Action=0 + Code[6]；等待 0x89 成功值 1。授权状态、配置、文件权限 60 秒。
首次绑定设备点“首次绑定设备”，输入要写入设备的新 6 字节码。向 FA19 写入 V1 0x09，Action=1 + Code[6]。绑定成功后进行认证后初始化。
恢复初始认证码已认证状态点击入口，阅读二次确认后输入当前认证码。向 FA19 写入 V1 0x09，Action=2 + Code[6]。App 清除回连记录、文件下载断点并断开；设备侧格式化录音和配置。
认证窗口

认证有效约 60 秒。超时、连接断开或认证失败后，状态、配置、文件和录音控制按钮重新锁定，需要再次认证。命令真正写入前会再次检查认证窗口，避免排队后仍发送过期授权的命令。

状态页显示设备返回的数据；每项可用性由设备实际提供的端点和字段决定。

数据缺失

某一项读取失败或设备未上报时，页面显示“暂未读取”，不会使用虚构默认值。单项失败不影响其他已正常工作的设备功能。

设备录音控制

设备录音由固件实际执行；App 只在收到对应结果后更新状态。

开始、暂停、继续、结束

FA17 可用时开放
用户操作
  1. 认证成功后，打开设备详情中的“设备录音”。
  2. 未录音时点“开始录音”。
  3. 录音中可点“暂停录音”，暂停后可点“继续录音”。
  4. 录音中或暂停时点“结束录音”。
协议与状态
  • App 向 FA17 写入 0x07。
  • 动作值：开始 1、暂停 2、继续 3、结束 0。
  • App 等待 0x87；停止帧与活动帧按协议分别校验。
  • 操作期间按钮禁用并显示进度；超时、设备拒绝或断连时显示失败。

设备文件导入

文件导入将设备录音下载到 App 的本地记录。当前不向设备发送“已归档/可删除”确认。

操作流程

FF12 / FF13 可用时开放
用户操作
  1. 认证成功后，设备详情点击“设备录音文件”。
  2. 等待文件列表加载；需要时点右上角刷新。
  3. 点击某条文件的“导入到记录”。
  4. 等待进度条完成；成功后该文件成为 App 本地记录。
传输流程
  1. App 使用 0x22 → 0xA2 分页读取列表。
  2. App 使用 0x23 请求文件数据。
  3. 设备通过 FF13 Notify 连续推送带 offset 的数据。
  4. App 校验 offset 连续、长度边界和零长度 EOF，完成后写入本地记录。
断点续传

下载中断时，已连续收到的字节和 offset 会作为本地 checkpoint 保留。再次导入同一设备、同一文件时，从 checkpoint 继续。

当前 EVT 文件边界

不使用旧单包读取；不使用 0x26 元数据/归档确认；不向设备发送删除或回收指令。设备原始文件继续保留。

回连与断开

回连只针对曾经完成认证和初始化的设备；用户主动断开不会在同一前台周期自动重连。

自动回连

回连规则

  • 保存最近一次成功设备的连接 ID、物理 MAC、显示名称和时间。
  • 扫描时优先按物理 MAC 匹配；iOS 无 MAC 时回退系统连接 ID。
  • 异常断连后最多尝试 3 次，重试间隔约 1 秒、2 秒。
  • App 进入后台暂停扫描和回连；回到前台后恢复。
主动断开

断开流程

  1. 设备详情点击“断开设备”。
  2. 确认弹窗后，App 取消订阅并断开 BLE。
  3. 当前会话进入中断状态，扫描列表可再次发现该设备。
  4. 用户可通过“重新连接”重新执行完整连接、认证和初始化流程。

设备检查与设备活动

设备检查是 App 本地的联调证据判断，不会额外下发固件自检命令。

使用流程

状态可观察时开放
用户操作
  1. 先让设备实际产生需要验证的状态或事件。
  2. 设备详情点击“设备检查”。
  3. 选择检查场景，查看通过、失败或不可验证的原因。
  4. 点击“保存验证结果”或提交人工观察，写入“设备活动”。
检查场景
  • 设备访问：检查当前状态是否可读取。
  • VAD 录音：检查 录音开始 → 静音结束 事件顺序和最终待机状态。
  • 电池与充电：要求电量和充电字段存在。
  • 待机功耗：要求功耗字段存在；当前 EVT 通常无该字段。
  • 恢复验证：根据已有状态快照判断恢复结果。
  • 物理反馈：保存用户填写的人工观察备注。
限制

页面使用进入时的最新状态快照和本次会话已收到的事件，不会重新执行录音、恢复或功耗测量。当前“恢复前/后”没有独立两次采集，因此它适合联调证据记录，不替代自动化产测。

实时日志

日志用于定位扫描、连接、认证、命令、文件传输和回连问题。

App 内查看

入口与能力

  • 设备详情右上角点击“实时日志”。
  • 支持自动跟随、暂停跟随、清空当前视图。
  • 记录扫描、连接状态、服务发现、订阅、收发命令、认证、状态读取、文件导入、断连和回连。
  • 日志会过滤音频正文、转写正文、完整 BLE 原始载荷和敏感路径。
Android Debug 文件

日志位置

Download/AIPIN/logs/aipin-YYYY-MM-DD.log

主日志在 App 私有 Support 目录的 logs 下；单文件约 5 MB 自动轮转，最多保留 7 个文件。Android Debug 成功镜像后可从公共下载目录取得文件。

限制

持久日志和 Android 公共镜像仅在 Debug 构建启用。日志页的“导出”图标当前只确保日志落盘并取得路径，没有接入系统分享回调；要获取 Android Debug 日志，优先从 Download/AIPIN/logs 读取。

协议与特征值映射

当前 EVT App 仅使用下列命令和端点。所有普通命令串行执行，默认约 2 秒超时并最多重试一次。

逻辑用途特征值 / 命令App 行为设备要求
V1 认证FA19 / 0x09 → 0x89发送认证、绑定或恢复初始码动作。FA19 必须 Write + Indicate；成功回复单字节 1。
设备信息0x01 → 0x81认证后读取并验证 ProtocolVersion=3。返回合法设备信息。
默认配置0x02 → 0x82认证后写入 EVT 默认配置。返回配置结果。
存储、状态、电量0x05 / 0x06 / 0x11自动或手动读取，显示在设备详情。从正确特征值返回匹配响应。
设备录音FA17 / 0x07 → 0x87开始、暂停、继续、结束录音。按动作返回正确录音状态帧。
文件数量、列表、数据0x21 / 0x22 / 0x23读取文件和接收连续数据流。FF13 Notify 数据 offset 连续，并以零长度 EOF 结束。
当前订阅顺序

必需顺序为 FA19、FA11、FA12、FA15、FA16、FA17、FB11、FF12、FF13，任一 CCC 订阅失败都会中断会话。设备提供 FF11 时，App 最后订阅其可选文件数通道；缺失或失败只是不显示文件数摘要。当前不订阅 FA18、FF16 或 WQOTA 服务。

业务帧格式 
[0xED][Length Low][Length High][CMD][Content ...][CRC Low][CRC High]

长度为小端序，CRC 为对 CMD + Content 计算的 CRC-16/CCITT-FALSE，并以小端序放入帧尾。App 会校验同步字、长度、CRC、命令号和响应所属特征值。

联调前置条件与限制

问题App 当前处理联调先检查
扫描不到设备不显示无名称设备；有名称设备可手动尝试连接，之后由 GATT 合约决定是否可用。蓝牙、权限、设备是否提供本地名称；自动回连再检查名称、A3 89 厂商数据和 6B 地址。
连接后无法认证任一必需 EVT 端点缺失、属性不符或 CCC 订阅失败时中断；FF11 不阻断认证。九个必需 GATT 特征的属性、CCC、系统配对/加密状态、0x09 和 0x89 抓包。
认证后功能不可点60 秒授权到期或连接中断时锁定功能。认证时间、是否断连和完整 EVT GATT 合同是否仍保持有效。
文件导入失败offset 不连续、长度越界、无 EOF 或 15 秒无下一帧时失败。文件列表、FF13 通知顺序、offset、数据长度和零长度 EOF。
