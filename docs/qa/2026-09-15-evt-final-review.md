## 本轮确认并修复

| 问题 | 修复与验证 |
| --- | --- |
| 设备已执行录音命令，但控制响应丢失后，刷新不能恢复录音状态 | `SessionController` 刷新时补读 `0x01`，按真实 RecordStatus 更新快照，保留认证和连接代次检查。不重复发送非幂等 `0x07`。回归覆盖开始、暂停、结束回包丢失后的刷新 |
| `RecordStatus=0xFF` 被误映射为待机 | `0x81` / `0x87` 的错误态映射为 unknown，显示暂时无法获取。两条路径均有回归 |
| 手机删除录音后设备文件页保留已保存标记 | 返回录音库、播放器、刷新列表及播放前检查本地文件，缺失则恢复保存入口；Shell 接入真实文件存在性检查。三项回归 |
| 从系统设置返回后权限显示不更新 | 权限行观察 resumed 生命周期并重新查询；回归覆盖 denied → granted |
| 本地录音库读取失败显示为没有录音 | 明确错误提示与重试，回归验证恢复后显示列表 |
| 检查记录读取失败显示为没有记录 | 明确错误提示与重试，回归验证恢复后显示正确空态 |
| 检查结果或人工观察保存失败没有反馈 | 显示保存失败，请重试；保留输入和再次保存能力。两条路径均有回归 |
| iOS 轮转历史日志镜像拒绝合法的不可变快照源文件 | 保留源目录约束，允许同一日志 stem 的严格 `.mirror-数字-数字` 快照格式；日常日志和手动导出仍要求合法文件名。Windows 仅完成代码审查，未执行 Swift/Xcode 验证 |

## 审查范围

- 发现与连接：Android 版本权限、非空名称扫描、目标选中、GATT 合约、订阅屏障、断线撤权、前后台回连。
- 认证与配置：6 字节安全码编码、首次绑定按键确认及后续 AUTH、认证后基线配置、授权与隐私、正常解绑门禁、解绑恢复。
- 设备录音：开始 / 暂停 / 继续 / 结束、命令互斥、响应丢失、未知或错误状态、显式状态刷新。
- 文件：完整分页、单活动下载、偏移与长度、结束帧、断点恢复、本地落库与删除后重新下载。
- 播放：预加载不自动播放、真实位置与总时长、未知时长禁拖动、暂停、结束重播、上一条 / 下一条、平台格式限制。
- 日志与证据：日志暂停恢复、清空与持久化区别、秒级导出、Android `.txt` 名称一致性、快照轮转、检查结论、人工观察及存储失败反馈。
- 页面：实际入口与条件、中文按钮、错误反馈、320 像素大字体布局、文档图文对应。

## 保留的验收边界

自动化和代码审查未发现尚未处理的确定正常主流程阻塞，但不能据此保证目标固件与实际音频全部正常。未执行真机 BLE 闭环、真实 OGG 文件时长/解码、大文件实传、iOS 构建与真机测试。

当前 `ProtocolVersion=3` 门禁仍按原 EVT 兼容策略跳过强制比较；GATT、字段与允许命令继续校验。当前不支持云端取码、设备文件归档/删除、实时音频、OTA。下载设备文件不会删除设备源文件，因此有设备文件时普通解绑门禁仍会阻止操作。

检查场景以已有事件与快照判断，不自动操作设备、采样功耗或执行恢复测试；当前页面传入的初始/最终快照相同，结果应作为已收集证据的判断，不冒充完整实验。iOS OGG 可下载但不支持当前原生播放方案。
