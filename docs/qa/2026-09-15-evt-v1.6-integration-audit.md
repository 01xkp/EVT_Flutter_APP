# EVT V1.6 联调代码审查

审查日期：2026-09-15。基线：`evt` 的 `9e1841c`（`0.0.2+3`）。协议依据为用户提供的《智能吊坠设备-App通讯协议_安全码简化与修订标注版_V1.6_20260914修正版.html》，SHA-256 为 `8547d1886d1254f55a9834a5c3d23ae532468a348f3ba8ee82f2fcaed80b8b85`。

本次检查覆盖当前 EVT 构建实际开放的功能：设备发现、GATT 连接与订阅、六字节认证/绑定/解绑、状态和配置、录音控制、文件列表、文件下载及续传、断线恢复。HTTPS 取码服务、实时音频、归档和 OTA 不属于这个 EVT 构建的实现范围。

## 已确认并修复的问题

| 问题 | 触发与影响 | 修复及证据 |
| --- | --- | --- |
| Android 12+ 扫描权限配置冲突 | V1.6 提交移除 `neverForLocation`，但定位权限只声明到 API 30，运行时只申请附近设备权限；RxAndroidBle 因缺少精确定位返回 UNAUTHORIZED | 恢复附近设备权限对应的 Manifest 标记；新增跨 Manifest/运行时策略回归测试，修改前失败、修改后通过；APK 解包确认标记值 `0x10000` |
| 正常解绑被 App 自身权限检查拦截 | 已认证用户开始解绑后，认证控制器先撤销业务权限，写入门禁随后把同一次解绑判为未认证 | 为从已认证状态开始的当前解绑操作保留窄范围写入许可；业务权限仍被撤销；使用真实认证控制器和会话控制器的组合测试验证 |
| 非法本地输入产生虚假解绑恢复状态 | 安全码格式在状态变更之后才校验，未发送给固件的操作也可能变为待恢复解绑 | 构造和校验请求后才变更认证状态；非法输入保持原连接权限，不产生恢复标记 |
| 已取消的排队下载仍发送请求 | `0x23` 尚未取得命令队列时取消订阅，稍后仍向固件发起传输 | 在队列执行入口识别取消，取消后不再写入；回归测试验证后续正常请求仍可执行 |
| 响应通道关闭后仍等待和排队 | 接收流正常结束没有通知挂起请求，导致继续等待超时或向失效通道发送后续命令 | 将流关闭视为传输终止，立即使挂起、排队和后续命令失败 |
| 普通状态查询重试仍被残留半帧阻塞 | 只清理命令层组帧器时，会话层特征组帧器仍可能缓存损坏的半帧，使正确响应无法到达命令匹配器 | 超时后按当前连接代次和请求特征同步清理会话层缓存；旧连接回调不得清理新连接，增加真实会话路径回归 |
| 文件数据被错误识别为另一帧 | 分片 `0xA3` 的音频数据恰好包含完整且 CRC 正确的 `ED` 帧时，旧组帧器可能抛弃外层帧并提前分发内部数据 | 不在尚未接收完整的外层帧中猜测新边界；两处生产组帧器限制 Length≤489，命令超时清理残留；验证最大 480B 数据分片、超长损坏帧头恢复及重试 |
| 文件页面同时发起不兼容操作 | 下载期间还能下载另一文件或刷新列表；退出页面后分页循环仍请求下一页 | 页面按单次下载互斥操作，退出后停止后续分页；新增交互回归测试 |

## 协议核对范围

| 链路 | 核对项 |
| --- | --- |
| 广播 | `A3 89 + BtAddressRaw[6]`、`AF30`、名称与厂商数据分片合并、Android legacy scan；手动 EVT 扫描按现有调试策略展示非空名称 |
| GATT | 九个必需特征及属性、可选 `FF11`；认证前订阅 `FA11/FA19`，认证后订阅业务特征；`FF13` 使用 Notify，其余响应按协议使用 Indicate |
| 帧与接收 | `ED / Length:u16LE / CMD / Content / CRC16`，CRC-16/CCITT-FALSE、小端编码、分片与合帧、提前回包、特征/CMD/SubCmd 匹配 |
| `0x01/0x02` | 身份/状态与时间字段、预认证和认证后读取、完整 `0x82` READ 回帧 |
| `0x05/0x11/0x21` | 存储、电量、可选文件数量响应布局和 GATT 操作 |
| `0x06/0x07` | 配置子命令、无数据成功响应、主动状态事件；停止/录音/暂停/错误状态，继续操作返回录音中；非幂等录音命令不自动重试 |
| `0x09` | `Action[1]+SecurityCode[6]`、绑定成功后的同连接 AUTH、设备按钮确认等待、解绑前置条件、解绑恢复与断连撤权 |
| `0x22` | 17 字节文件名槽、21 字节列表项、按实际 Count 推进 offset；只有 Count=0 才结束，短页继续读取 |
| `0x23` | 首次与续传请求、连续 offset、结束帧、长度一致性、MTU 限制及最多 480 字节数据、15 秒空闲超时、断点落盘与恢复 |
| 会话和界面 | 前台回连、手动断连、后台停止回连、权限门禁、状态刷新、下载操作互斥和页面释放 |

## 真机验收边界

首次代码审查时没有连接真机。随后已通过无线 ADB 将修复版安装到 Android 真机 `VER_AN10` 并启动；安装后 15:04 的日志显示蓝牙广播进入扫描流，非空名称设备已加入列表，确认原权限阻塞已消除。该证据尚不能证明目标 EVT 设备的鉴权、录音控制、解绑和文件续传已完成真机验收。Windows 环境无法完成 iOS/Xcode 构建。

使用修复后的 APK，按 `docs/real-firmware-integration.md` 第 7 节执行：首次授权扫描、已授权重扫、蓝牙开关、正确/错误安全码、绑定后的 AUTH、状态配置、录音开始/暂停/继续/结束、跨页文件列表、完整下载和中途断线续传、正常解绑及失败恢复。与固件日志核对每次 CMD、特征、回包及设备最终状态。

恢复 `neverForLocation` 与上一版保持一致；Android 可能对部分信标广播做系统过滤，因此仍须在目标手机上确认该固件的主广播与 Scan Response 都能被接收。若目标硬件确需取消该标记，必须同时设计、声明和申请定位权限，不能只改 Manifest 标记。
