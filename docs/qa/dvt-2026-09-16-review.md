# DVT V1.6 链路审查与交互回归（2026-09-16）

分支：`dvt`。App：`0.0.2+3`，包名 `com.aigutta.aipin`。依据 V1.6 修正版协议及现有 EVT 界面，保留 DVT 文件元数据/归档、实时音频验证、WQOTA。

## 已修复

| 链路 | 原问题 | 修复及回归依据 |
| --- | --- | --- |
| 二进制接收 | 未收完整的文件帧内出现合法 ED 字节序列时，可能误拆为另一个回包 | 按外层长度接收完整帧后校验；480B 文件/音频嵌套有效 ED 回归通过 |
| 接收长度 | 异常长度可能阻塞后续数据 | 业务响应 Length 上限 489，FA18 独立上限 483；坏头后有效音频集成回归通过 |
| 超时和断流 | 残留半包污染下一请求；响应流关闭后队列仍可写入 | 仅清理当前会话的对应特征半包；响应流关闭终止等待和排队请求；排队下载取消后不再发送 |
| 解绑 | 进入认证中状态后失去原权限，正常解绑可能被写入门禁拦截 | 只允许由已认证连接启动的当前解绑穿过专用门禁；格式先验证，解绑意图先持久化，断连后撤销许可 |
| 录音状态 | 只刷新 06 无法恢复丢失的录音状态响应 | 刷新增加 01 信息读取；未知/错误录音状态不映射为待机 |
| 文件归档 | FF16 原生写入/接收失败后迟到 A6 可能污染下一请求 | 提交后失败即隔离当前 BLE 会话；文件下载期间禁止并发元数据/归档操作 |
| OTA 传输 | 窗口等待超时后仍继续发送后续 E5 块 | 每块前检查等待结果，超时/接收异常停止后续发送 |
| OTA 页面 | 退出动画期间初始化完成，仍可能启动升级 | 同时检查页面挂载、正在退出、允许返回状态，释放准确的控制器；真实 Navigator 竞态回归通过 |
| 音频验证 | 启动通知异常且清理失败时停止操作丢失 | 保留统计与待停止状态，禁止重复启动，允许再次停止 |
| 文件页面 | 保存后没有直接播放、其他行也显示正在保存、本地删除后标记失效 | 按文件键区分进度，保存后提供播放；回页及播放前检查副本存在性；业务操作互斥 |
| 公共交互 | 权限返回未刷新、日志暂停与导出反馈、未知音频时长和检查记录失败不清楚 | 沿用 EVT 交互补齐恢复/失败/重试；播放器诊断接入本地 AUDIO 日志 |

设备详情调整为：连接状态 → 认证或录音控制 → 已保存录音 → 状态配置 → DVT 专项验证 → 设备检查 → 断开 → 折叠设备管理。安全码支持 6 位可打印文本或 12 位十六进制，最终仍为协议规定的 6 个原始字节。

## 联调边界

- 未连接真实固件，不将自动化结果当作实机验收。
- Windows 环境未执行 Xcode/iOS 编译与签名。iOS 按系统外设 UUID 连接，不假定 MAC 或可主动设置 MTU。
- FA18 固定 480B 音频需要实际 ATT MTU ≥489；不足时明确拒绝。当前 iOS OGG/Opus 本地播放能力仍受限。
- 归档需配置 `DVT_ARCHIVE_URL`，并由服务返回与原文件匹配的可靠保存回执；默认未配置时不允许设备释放文件。
- OTA 需有效 HTTPS 清单、真实镜像、目标抓包帧头及 E8 最终校验语义依据；传完后仍必须重连认证、核对设备版本。
- 保留临时 ProtocolVersion 只记录不拦截规则；业务命令、GATT 属性、长度和校验仍严格检查。
