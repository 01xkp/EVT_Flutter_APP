# v0.0.1 EVT 联调版本变更说明

- 日期：2026-09-10。
- 分支：`evt`，推送目标：`origin/evt`。
- Flutter 版本配置：`0.0.1+2`。
- Android：`versionName=0.0.1`、`versionCode=2`。
- iOS：`CFBundleShortVersionString=0.0.1`、`CFBundleVersion=2`，由 Flutter 构建变量传入。
- 包名保持 `com.aigutta.aipin`。本次仅覆盖 V1.5 EVT 调试，不扩展 V2、云端认证或 OTA。

## 1. BLE 接收与连接修复

1. Android 保持 RxAndroidBle 外层订阅存活，移除会在 CCC 建立后立即释放监听的截断操作。
2. CCC 配置完成且持续回包监听已安装后才报告就绪。监听异常或意外结束会明确上报，不继续展示虚假的接收就绪状态。
3. 保持 V1.5 订阅方式：控制响应使用 Indicate，FF13 文件数据使用 Notify。
4. Dart 接收包装层改为可直接传递取消的流转发，设备静默时也能退出监听，不阻塞断连与后续重连。
5. 回包等待在原生写入前注册。回包或接收错误先于写入完成时，不丢失结果，也不产生无人处理的异步错误。
6. Android 增加扫描停止后的短暂冷却，减少紧接着重新扫描时的注册冲突；未处于自动回连扫描阶段时不反复生成无意义回连日志。

## 2. 认证与旧会话隔离

1. 认证、首次绑定、恢复认证码及文件操作记录发起时的连接代次，旧操作结束后不能断开或覆盖新连接。
2. 手动断连、重试连接时撤销旧授权，旧请求失败不再污染当前页面提示。
3. 认证控制器释放后不再设置授权状态、启动到期计时器或通知已销毁的页面。
4. 保留输入框打开、取消、确认、发送、接收、业务结果、认证后同步及终态落盘日志。

## 3. 新增回包等待日志

普通命令和连续文件回包共用等待日志组件。日志只观察状态，不增加查询、重发或延长协议超时。

| 日志事件 | 含义 |
| --- | --- |
| `evt_response_wait_started` | 响应等待已登记，准备写入设备，业务响应超时尚未启动 |
| `evt_command_transmit_started` / `evt_stream_command_transmit_started` | 开始调用 GATT 写入 |
| `evt_command_transmit_completed` / `evt_stream_command_transmit_completed` | 系统写入操作完成，不代表设备业务处理成功 |
| `evt_response_wait_armed` | 从系统写入完成开始计算业务响应超时；若提前收到完整回包，则不会再出现此日志 |
| `evt_response_waiting` | 等待期间每秒一条，区分系统写入等待与设备响应等待 |
| `evt_response_wait_finished` | 本次等待结束，`state=success/failed/cancelled`，中文原因说明收到、超时、中断或取消 |

等待日志包含 `wait_id`、`characteristic`、`command`、`expected_command`、`attempt`、`timeout_ms`、`elapsed_ms`、`response_count`。系统写入完成后增加 `idle_ms` 和 `remaining_ms`。同一次发送、匹配响应和等待日志可按 `wait_id` 关联；重试分配新的等待编号。

普通命令收到完整匹配帧即停止等待日志；无关帧或校验失败帧不能结束等待。文件连续回包在收到中间帧后继续等待并更新空闲计时，直到终止帧、超时或取消。`state=success` 仅证明收到匹配回包，设备业务成功与否仍以响应字段及后续业务校验为准。

日志间隔由事件循环调度，不是硬实时的一秒。手机挂起进程时不保证持续输出；当前实现不以增加日志为理由新增后台保活。

## 4. 定位接收断点

认证 `0x09 -> 0x89` 可按以下证据顺序排查：

1. `characteristic_subscription_ready`：Android 原生持续订阅就绪。
2. `notification_subscription_ready`：App 订阅就绪。
3. `evt_response_wait_started`：本次命令等待已登记。
4. `evt_command_transmit_completed`：系统写入完成。
5. `characteristic_packet_received`：Android 原生已收到设备回包，准备转发到 Dart。
6. `notification_received`：Dart 已拿到字节。
7. `notification_frame_forwarded`：帧有效且属于当前特征，转发命令匹配器。
8. `evt_command_response_matched`：回包匹配当前命令。
9. `evt_response_wait_finished state=success`：结束等待，再检查认证业务结果和同步结果。

第 5 至 9 步可能早于第 4 步，属于支持的提前回包顺序。没有回包时应看到等待日志和超时终态，而不是只留下发送完成。Android `characteristic_packet_dropped` 表示原生收到数据但 Flutter 通道无监听。CRC 或响应特征不匹配时会另有解码失败或隔离日志。

## 5. 日志保存与平台边界

- Debug 日志先写应用私有 `logs/aipin-YYYY-MM-DD.log`；Android 公共镜像位于 `Download/AIPIN/logs`，可在设备页实时日志入口查看实际状态并导出。
- 私有日志写入与公共镜像分离，公共目录权限或复制耗时不阻塞 BLE 命令。当前 APK 最低 Android 7；Android 7-9 仅在用户主动导出时请求旧版存储权限，自动落盘不弹权限框；Android 10+ 使用系统公共目录机制。
- 认证操作结束及应用进入后台时补充刷盘；公共镜像有超时限制，轮转文件先制作快照，避免慢镜像复制到已改名的后续文件。
- 原生控制收发增加中文前缀、特征实例、错误和字节信息；完整原始包由 Debug 日志保留。FF13 原生层做计数采样，完整字节仍由 Dart 接收层记录，避免重复记录大段音频。
- Release/Profile 不开启这套持久化调试日志。Debug 原始字节可能包含认证码和音频，应只在受控联调环境使用。
- 本次在 Windows 完成 Android 构建和自动化验证；iOS 原生构建、系统权限及真实设备收发仍需 Mac 和真机验证。
